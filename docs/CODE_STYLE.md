# Code organization and reproducible runs

`GameDatabase` returns each operation's result directly. `RecordResult` distinguishes `Updated`, `Unchanged`, `Invalid` and `StorageError`. `BestTimeResult` combines a storage status with an optional time, so a missing score is different from a failed query. Profile operations return a status and their committed profile list. Callers update their displayed state only after success.

Schema creation and text-file imports live in `DatabaseMigrations.cpp`. Reusable SQL queries live in `DatabaseQueries.cpp`, and the scoped SQLite connection, statement and transaction owners live in `Sqlite.h`. The runtime database API accepts an alternative path for isolated tests. The database filename, schema and legacy migration markers remain compatible with existing saves.

`Renderer` draws world geometry and lighting. `RendererExit.cpp` draws the exit door in the normal material and emissive lighting passes. `HudRenderer` draws translucent timer digits at the top center after the 3D pass. E reveals a large translucent map of explored cells for one second on normal grids up to 30 x 30, or two seconds on larger grids and in Zero Gravity. The three-second cooldown starts when either peek closes. `MapPeek` advances only during active gameplay and resets with each run; pause and result rendering omit peek state so those screens cannot expose a frozen map. Embedded GLSL lives in `MazeShaders.h` and `MazeLightingShader.h`; no external shader files are required at runtime. `Textures` is a move-only GPU resource owner. Borrowed handles are exposed through accessors for drawing, while destruction and move assignment release owned resources automatically. Keep resource owners inside the graphics context's lifetime.

`CorridorStyle` supplies the gilt molding and lighting roles for the loading-screen-inspired wall design. Upper walls use bronze damask with carved gold corner ornaments; dark marble wainscoting sits below them. Separate honey marble covers 3D pilaster fronts and returns with a consistent world-space texture density. Stepped capitals and bases, rails and frames supply the shallow relief. Twin flared opal-glass cups on curved brass arms use the existing light selection and emission passes. The marble material shares `Textures` ownership, move and lifetime rules. The Persian carpet retains its cream, crimson and near-black pigments, with a scalloped floral medallion and continuous floral border. Its full-color atlas is cached on the CPU, then uploaded into each material set; lamp lighting shades the weave naturally. A 2048-by-1024 atlas contains a 1024-pixel field and a separate border strip; mipmaps and anisotropic filtering preserve the pattern at grazing angles. `CarpetLayout` keeps atlas regions and border width aligned with floor mapping. Field and border patches meet without overlapping, with miters at inside and outside corners. Architectural relief is drawn only near the camera's view. Maze layout, collision and gravity remain unchanged.

The atmosphere vertex shader receives world-space vertices from rlgl's immediate-mode batch. Its CPU-side primitive transforms are already baked into those vertices; applying `matModel` again would corrupt lighting when the buffer fills during a transformed primitive. GPU checks cover both ordinary draws and automatic full-batch submissions.

The atmosphere shader evaluates up to sixteen nearby wall and ceiling fixtures in linear color, using rectangular emitters and smooth finite-range inverse-square attenuation. Explicit material uniforms provide roughness, metalness, relief height, clear-coat strength and the wall/wainscoting layout. GGX distribution, correlated Smith visibility and Schlick Fresnel give stone, gold, wallpaper and wool distinct responses. Material changes flush the preceding geometry before updating uniforms. Packed maze-wall masks block light between corridors and are refreshed when maze size or seed changes. The light list follows the camera; material lighting and emissive fixtures remain separate passes.

Five weighted diffuser samples soften brighter shadow edges. Analytic contact/corner occlusion, palette-tinted bounce and local source reflections add depth. Texture derivatives supply restrained relief with distance fading and specular filtering. Wallpaper and carpet remain rough. A faint visibility-tested scattering term follows each fixture. `Bloom::begin(true)` draws linear scene radiance into a full-resolution RGBA16F target, then extracts and blurs highlights in two half-resolution RGBA16F passes. Composition adds restrained bloom, applies the filmic display curve and converts to sRGB before the HUD. Targets are reused, replaced on resize and released within the graphics context; direct rendering remains available when HDR is unavailable. The default `Bloom::begin()` keeps the previous sRGB composition behavior.

Maze generation uses an explicitly seeded `std::mt19937`, independent of theme selection and decorative texture generation. It grows mainly from the newest passage, occasionally resuming an older branch to add junctions. Six candidates share the same dimensions and passage density; selection favors decision points and turns on the exit route while penalizing excessive walking distances. Only the selected candidate's carving steps reach the generation preview. Existing level sizes, timers, corridor geometry, spawn and exit stay unchanged. To reproduce a loaded run, supply its seed and selected theme along with the same level parameters:

```cpp
Game reproduced(size, duration, original.mode(), original.seed(), original.theme());
```

`ActiveMazeTheme` in `src/data/MazeTheme.h` currently selects Grand Hotel for all normal application flows. Default `Game` construction uses the same theme regardless of seed or mode. Supplying a theme explicitly remains useful for material previews. Maze seeds still determine layouts independently of the fixed color palette.

The application applies the curated theme at startup, on menu return and when starting or retrying a run. Player/level selection, generation, gameplay, pause and results all retain it. The optional seeded theme selectors remain available for future collections, but application navigation does not instantiate or consume them.

`MenuTheme::colorsFor` derives all interface materials from a maze palette. `MenuTheme::apply` updates the live color references used by drawing helpers and their default arguments. Main-menu and background color aliases must remain references so existing screens update without reloading fonts or recreating their geometry. The HUD uses the same palette factory for its active run.

`MenuBackground` shares four connected corridor views, a grading shader and a reusable foreground target across menu screens. A weak cache retains no GPU resources after the screens are destroyed. Wall fabric takes the curated warm palette while carpet reds, gold, marble and lamp highlights retain the artwork's lighting. Perspective yaw, dolly and phased scene overlap carry the camera between the entrance, player junction, right-hand gallery, left-hand vestibule and mirrored Controls branch. Continuous, bounded pan, yaw and zoom animate each idle view; the grading shader gently varies bright lamp highlights. Foreground UI stays in screen space. Cover cropping fills every window shape. The centered T1 wordmark uses the bundled Ballet calligraphy font, rasterized at a higher resolution and fitted by its visible glyph bounds so its wide swashes remain centered and clear of navigation. The font and its SIL Open Font License travel together under `assets/fonts/`.

`MenuJourney` owns pure route and timing state. Application defers navigation during a 0.9-second trip, fades source/target UI independently of the corridor, and ignores repeated input until arrival. Back from level selection returns to the player junction with the turn reversed. New-player/custom choices and the Controls diagram move within their current stop over 0.38 seconds; cancelling restores that view without accumulating zoom. A selected run is created before travel to the vestibule, but neither generation nor gameplay advances during the trip. Its first travel frame discards stale frame time from material preparation; the full mandatory 4.5-second generation preview starts after arrival. `Build.props` copies all `src/assets/*.png` artwork beside the game and core-test executables; packaged paths precede working-directory fallbacks.
